## Upgrade/configuration sequence (planner/operator; not executed against live hosts)
1. Planner reviews scoped commit and matching final build.json/source/artifact digests. Preserve immutable prior receipts/bundle and existing enrollment descriptors. Update only the current project artifact-selection and management descriptor authority to the reviewed source/build/CLI/guest/manifest hashes; do not overwrite historical receipts or restore old catalog over new writes.
2. Planner extends only the existing dedicated local CLI tunnel allowlist with literal `ubuntu\\.ext4` and `network-tools\\.tar\\.gz`, validates exact path matches, and performs their scoped tunnel restart. CLI Access app already covers `/cli/*`; **no Access app, API, policy, DNS or global SSL write is required**. Helper recognizes the old five-file expanded predecessor and supports repeat/rollback preserving unrelated routes.
3. Owner: `ow host budget NODE --memory RAM_MIB --cpus VCPU_BUDGET --slots SLOTS` or per-node dashboard Adjust budget. For decreases, use an online idle host first and resolve all demand; offline lowering rejects. Do not select remote budget before owner supplies CPU topology and explicit budget.
4. Operator intentionally stops their live test guest by their choice, then **using the OLD installed CLI** run `ow --data-dir HOST_ROOT host stop` **before replacing its executable**. Do not install then stop: an old running worker may retain a deleted executable inode that a new CLI cannot positively identify. CLI updater installs only the binary/helper; it preserves saved host.json/node.json/assets/disks. Use the existing installer URL after planner publishes the reviewed binary (or verified private binary transfer); keep prior CLI for rollback.
5. Operator: `ow --data-dir HOST_ROOT host update-assets --ubuntu-dev`, then `ow --data-dir HOST_ROOT host configure --memory RAM_MIB --cpus VCPU_BUDGET --slots SLOTS --accept-shared-pool` (optionally `--storage-gib RETAIN_GIB`). Refresh needs full selected logical transfer + saved reserve + 512 MiB overhead, with prior assets retained. New joins opt in using `host join --ubuntu-dev`; default stays Alpine-only.
6. Operator explicitly `ow --data-dir HOST_ROOT host start`, checks `host status`; owner checks effective node capabilities. Create: `ow create NAME --image ubuntu --memory 4096 --cpus 2 --node NODE`. Cold resize: stop that owned workspace, `ow resize NAME --memory 4096 --cpus 2`, then start; no live resize or migration.
7. Asset rollback while stopped: `ow --data-dir HOST_ROOT host rollback-assets --revision assets-rollback-NONCE`; prior revision is verified and reflink-copied, current selection retained. Select prior binary separately only if compatible (older Alpine CLI cannot interpret v2 Ubuntu manifest; select matching prior assets). Restore prior consent budgets with supported configure, never manual JSON/SQLite patches. No disk/catalog rollback.
